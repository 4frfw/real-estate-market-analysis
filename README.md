# Исследование рынка недвижимости

Динамика цен и влияние макрофакторов.

- Автор: Чичилов Кирилл.
- Группа: ЧЛБ25-ИУП-БИ01.
- Дисциплина: «Технологии хранения данных».
- Тема: №9.
- Объект: первичный и вторичный рынки жилья России.
- Период: 2019–2024 годы, шесть годовых наблюдений.

## О проекте

Проект объединяет хранение открытых данных, проверку качества, расчёт показателей, электронную таблицу и интерактивную визуализацию. Цель — сопоставить сегменты, отделить номинальную динамику от инфляции и проверить наблюдаемые связи с макрофакторами.

Это фиксированный исторический срез, а не обзор текущего рынка 2026 года. Причинное влияние макрофакторов и надёжный прогноз по шести точкам не заявляются.

## Основные результаты

| Показатель | Первичный рынок | Вторичный рынок |
|---|---:|---:|
| Изменение средней цены за 2019–2024 годы | +177,54% | +95,04% |
| Реальный прирост индекса цен за 2024 год | −0,66% | −2,67% |

Превышение средней цены первичного рынка над вторичным в 2024 году составило 55,92% к вторичному рынку.

Выводы:

1. Средняя цена первичного сегмента выросла сильнее вторичного.
2. В 2024 году приросты индексов обоих сегментов оказались ниже инфляции.
3. Изменение средней цены не равно приросту опубликованного индекса.
4. Корреляции чувствительны к отдельным годам и не доказывают причинность.

Числа сверены с `reports/summary.json`.

## Запуск расчёта

Из корня репозитория:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/analyze.py
```

Результаты сохраняются в `data/processed`, `reports` и `site`. После расчёта открыть `site/index.html` локально в браузере. Библиотека Plotly вложена в проект; для основных графиков CDN не требуется. Доступны ползунок диапазона, легенда и масштабирование.

Excel содержит листы `Data`, `Correlations`, `Scenarios`, `Statistics` и `Formulas`. Готовые значения доступны независимо от пересчёта формул приложением.

## Методика и ограничения

- Изменение средней цены: `(Pтек / Pпред − 1) × 100%`.
- Прирост индекса: `опубликованный индекс − 100%`.
- Реальный прирост индекса: `(индекс / (100 + инфляция) − 1) × 100%`.
- Разрыв сегментов: `(первичный / вторичный − 1) × 100%`.
- Корреляции рассчитаны для приростов индексов и макрофакторов; n = 6.
- Исключение одной точки — проверка чувствительности, не доверительный интервал.
- Ключевая ставка взята на конец декабря: это не среднегодовая и не ипотечная ставка.
- Сценарии кредита: 6 млн руб., 240 месяцев; ставки 8%, 12%, 16%, 20% — допущения, не предложения банков.

Жилищные ряды взяты из перепубликации Росстата на Roschart. S1 не является официальным сайтом Росстата; первичный XLS не включён. В S1 исключены Крым и Севастополь, поэтому охват отличается от общероссийского макроряда. Полные ссылки и точность ввода раскрыты в [реестре источников](data/sources.md).

## Автоматизация

| Workflow | Назначение |
|---|---|
| [Analytics and Pages](.github/workflows/analytics.yml) | Тесты, расчёт, сохранение результатов и артефактов, попытка публикации Pages |
| [Weekly verified backup](.github/workflows/backup.yml) | Архив, SHA-256, проверка восстановления и выпуск релиза; понедельник 03:00 UTC или ручной запуск |
| [Capture actual progress](.github/workflows/progress.yml) | Снимки фактического остатка Issues и построение burndown |

Автоматический расчёт подтверждён коммитом `d128d9d` от GitHub Actions: в репозитории появились Excel, обработанные CSV и HTML. Этот коммит сделан до шага публикации Pages, поэтому сам по себе не подтверждает успешный deploy.

Сбор прогресса требует реальных Issues. Первый снимок — одна точка; для линии нужны минимум два наблюдения. История задним числом не создаётся.

ZIP и Git bundle резервируют файлы и историю Git, но не сущности Wiki, Issues, Discussions и Projects. Для них нужен отдельный экспорт, для независимого резерва — копия вне основного аккаунта.

Наличие workflow или Markdown-шаблона не заменяет работающий сервис. Полное выполнение всех девяти работ пока не подтверждено.

## Что осталось для полной приёмки

1. Опубликовать Wiki и Discussion, создать реальные Issues и получить настоящий ответ участника.
2. Создать и заполнить Projects, собрать фактические снимки burndown.
3. Подтвердить успешный Pages deploy и доступность дашборда по публичной ссылке.
4. Выполнить резервный workflow, проверить релиз и восстановление, сохранить независимую копию.
5. Согласовать итоговые Word и презентацию с фактическим состоянием GitHub и представить результаты лично.

Документы Word, PDF и слайды являются зафиксированной аналитической версией и не обновляют текст выводов автоматически при изменении CSV.
