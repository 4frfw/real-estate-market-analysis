# Запуск, обновление и восстановление

[Главная](https://github.com/4frfw/real-estate-market-analysis/wiki/Home) · [Методика](https://github.com/4frfw/real-estate-market-analysis/wiki/Methodology)

## Локальный запуск

Команды выполняются из корня скачанного или клонированного репозитория. Нужен Python с зависимостями проекта; для резервирования истории Git также требуется Git и полноценная копия репозитория с каталогом `.git`.

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/analyze.py
```

Результаты: обработанные CSV в `data/processed`, `reports/summary.json`, `reports/market.xlsx`, `site/index.html` и локальная библиотека Plotly. Excel включает листы Charts, Conclusions и Guide. Откройте Excel в табличном редакторе для пересчёта листа Formulas; Data и Conclusions уже содержат числовые значения. HTML можно открыть локально.

## Обновление данных

1. Обновить CSV в `data/raw`, сохранив структуру столбцов и согласованные периоды.
2. Обновить происхождение и точность данных в `data/sources.md`.
3. Запустить тесты и расчёт. При расширении периода проверить также подписи периода, размер выборки в корреляционных таблицах и текстовые выводы в коде, README и Wiki: не все такие подписи вычисляются автоматически.
4. Проверить показатели, диаграммы, единицы и ограничения интерпретации.
5. Сохранить изменения в Git.

Расчёт пересоздаёт `reports/market.xlsx`. Изменения оформления нужно вносить в генератор, а не только вручную в итоговую книгу.

## Actions и Pages

Workflow Analytics and Pages выполняет тесты, расчёт, сохранение результатов и развёртывание сайта. Для ручного запуска: Actions → Analytics and Pages → Run workflow → main. Для первоначальной настройки публикации: Settings → Pages → Source → GitHub Actions.

Ссылка на файл `site/index.html` не заменяет публичную ссылку Pages. Публикация считается проверенной после успешного deploy и открытия сайта в браузере.

## Резервирование

После расчёта можно выполнить:

```bash
python scripts/backup.py
```

Скрипт создаёт `backup/project.zip`, при наличии `.git` — `backup/history.bundle`, а также `backup/checksums.json` и `backup/restore.json`. Проверяются SHA-256, целостность ZIP, тесты и повторный расчёт восстановленной копии; итоговый JSON сравнивается с исходным. Для Git bundle выполняются клонирование и `git fsck`. Успешный результат — сообщение `RESTORE PASS` и значение `PASS` в `restore.json`.

Workflow Weekly verified backup содержит еженедельное расписание и ручной запуск; после успешной проверки публикует резервные файлы в Releases. Наличие конфигурации не доказывает успешное выполнение: результат нужно подтверждать журналом запуска и файлами релиза.

ZIP и Git bundle не экспортируют отдельные сущности GitHub: Wiki, Issues, Discussions и Projects. Для их сохранения нужна отдельная процедура. Независимую копию релиза следует сохранить вне этого репозитория.

## Ручная проверка восстановления файлов

В отдельной папке распаковать `project.zip`, установить зависимости и запустить тесты и `scripts/analyze.py`. Сопоставить `reports/summary.json` с версией из архива, открыть Excel и HTML. Для проверки истории клонировать `history.bundle` в новую папку и выполнить `git fsck --full`. Контрольные суммы файлов сверять с `checksums.json`.

Восстановление файлов не создаёт автоматически сайт Pages, Wiki, доску Projects или обсуждения. Учебный тест восстановления не является гарантией RTO или SLA. Токены и другие секреты в файлах проекта хранить нельзя.
